# 漏洞验证手册（真实性验证关卡）

> 阶段 3 的操作依据。每个候选漏洞按对应条目完整验证，做到：专业工具完整验证、复现利用链、危害闭环 A-B-C（修改前状态 → 操作 → 修改后状态）、证据固定、最小影响。**验证不出完整链条 = 误报，写入 rejected 清单——这条是第一不可违背原则，没有任何例外。**

## 专业工具验证链（先读）

补天官方规则（为什么必须验证）：FAQ 审核不通过首因 = "漏洞无法复现"；收录细则 = "复现失败将作忽略处理"、"未经人工验证的AI生成的漏洞（多次提交可能面临封号风险）"；提交须知 = "漏洞利用的完整过程：相关URL、截图、代码及POC，若不符合规则，漏洞可能会审核不通过"。验证的产出不是"我觉得存在"，而是**厂商审核员照着证据能一步不错地复现**。

### 工具分层（开始验证前先探测本机可用性：`which sqlmap nuclei httpx nmap curl` / `python --version`）

| 层 | 工具与命令 | 用途 | 纪律 |
|---|---|---|---|
| ① 专业工具 | `sqlmap -u "<URL>" --batch --level=1 --risk=1 --threads=1 --dbs` | SQL 注入自动化确认 | **止步于 `--dbs`**（官方中危门槛=证明可取库名），禁止 `--dump` 拖数据；`os-shell`/`--file-*` 一律禁用 |
| ① 专业工具 | `nuclei -l urls.txt -severity low,medium,high -exclude-tags dos,intrusive -c 10` | 已知 CVE/组件漏洞批量确认 | 命中结果只是"高置信线索"，必须按对应条目手工复核后才算验证（通用漏洞是刷洞/蜜罐重灾区） |
| ① 专业工具 | `httpx -l subs.txt -title -tech-detect -status-code`、`nmap --top-ports 100 -sV` | 存活、指纹、服务识别 | 限速；只作侦察与指纹证据 |
| ② 定制 PoC | Python `requests`/`urllib` 自写 `poc.py` | 布尔/时间差对照注入、越权对照、未授权访问、签名绕过等自定义利用链 | 每个确认漏洞**必须**产出一个可重复运行的 `poc.py`：内置目标参数、自动断言、末行打印 `VULNERABLE/NOT VULNERABLE` 与关键证据；这是官方"代码及 POC"要求的核心证据 |
| ③ 取证 | `curl -v`、浏览器 devtools、browser-use 技能 | 原始报文、GUI 截图 | 逻辑/越权类必须用浏览器以真实用户视角复现一次并截图 |
| ④ 兜底 | curl + Python 标准库手写请求 | 工具缺失时 | 工具缺失不是跳过验证的理由，只是多写几行代码 |

### 通用验证纪律

1. 亲自发请求拿原始响应，不引用扫描器输出当证据（工具输出可作为**附件**，但报告正文引用的是你自己的报文与 PoC）。
2. 每类验证先在"自己可控的正常状态"取基准 A，再触发操作 B，对比出危害结果 C。
3. 证据五件套：`poc.py`（可重复运行）、完整请求报文、完整响应报文、复现截图、验证笔记（含时间戳与重现性矩阵）。
4. **重现性矩阵**：独立会话重复 ≥2 次 + 跨时间点 ≥1 次，全部一致才算通过；时间盲注必须带无 payload 的对照组基线（网络抖动是时间盲注误报的第一来源）。
5. 最小影响：取证即停。注入 `--dbs`/LIMIT 1~3、越权看 1~2 条、文件泄露只读头部、不写入不删除不压测。
6. 重测防假阳性：加随机 cache-bust 参数、用无痕会话/全新 Cookie、换时间窗再验，结果必须稳定一致。

## 越权（水平/垂直越权）—— 中危~高危

**线索**：接口带 `id/uid/orderId/userId` 等可遍历参数；页面隐藏管理接口；JWT 无失效。

**验证步骤**：
1. 注册两个测试账号 A、B（无注册入口则在授权范围内用厂商提供的测试账号，绝不能用真实他人账号做写操作）。
2. A 登录，记录 A 能访问的资源列表与接口响应（状态 A）。
3. 保持 A 的会话，把请求中的资源标识改为 B 的（或遍历 +1/-1），重放（操作 B）。
4. 响应返回了 B 的数据 → 水平越权成立（状态 C）。A 的会话能访问管理员接口/功能 → 垂直越权成立。
5. 取证：只保留 1~2 条越权记录的脱敏响应，注明"已立即停止，未批量拉取"。

**误报排除**：响应 403/空数据/统一错误页 = 无越权；返回的是 A 自己的数据（参数实际没生效）= 假阳性；公开信息（新闻、商品详情）不算越权。

**定级要点**：垂直越权到管理功能、越权可致批量数据泄露 = 高危；仅能看少量非敏感他人信息 = 中危。

## SQL 注入 —— 高危（视业务）

**验证步骤**：
1. 定位注入点（搜索框、排序参数、Cookie、Header、JSON body），先用**只读、无害**的探测：布尔差异（`' AND '1'='1` vs `' AND '1'='2`）、时间盲注（`AND SLEEP(3)`，注意只发 2~3 次确认延迟稳定）、报错回显。
2. 确认可控后，用 sqlmap（`--risk=1 --level=1 --threads=1`，禁止 `--dump` 全表）或手工证明可取数。
3. **危害证明**：`UNION SELECT` 或报错注入取出**当前数据库用户/数据库名 + 1~3 行样例数据**（脱敏），证明真实数据可控，到此为止。
4. 记录：完整 URL、参数、payload、响应证据。

**误报排除**：WAF 拦截页/统一异常页 ≠ 注入成功；`SLEEP` 延迟可能是网络抖动——需对照组（同请求不带 payload 的响应时间）；单引号报错回显（`You have an error in your SQL syntax`）只能算线索，必须证明可取数。

**定级要点**：核心业务库可取敏感数据 = 高危；废弃/测试库、仅可报错 = 视影响降级。

## 命令执行 / 反序列化 / 组件 RCE —— 高危

**验证步骤**：
1. 指纹确认组件与版本（响应头、报错页、favicon hash、路径特征），核对已知 CVE 的**影响版本区间**。
2. 优先用**无危害回显验证**：DNS/HTTP 外带（自建或用 dnslog 类平台，`whoami.<dnslog>`）、`echo` 标记串回显、时间延迟。
3. 禁止：下载 webshell、执行删改命令、读写敏感系统文件、反弹 shell 到目标内网。证明"命令可控"即止。
4. 记录版本、payload、外带证据截图。

**误报排除**：版本匹配但补丁已热修；漏洞路径 404；回显来自 WAF 仿真响应（对比多次响应一致性）。蜜罐高发区——特征过于"完美"的开放服务要警惕。

## 逻辑漏洞（支付/密码重置/验证码）—— 中危~高危

**验证步骤**（以 0 元支付为例）：
1. 正常下单流程走到支付前一步，记录订单金额与状态（状态 A）。
2. 抓包修改：金额改 0/0.01/负数、数量改负数、优惠券重复应用、直接跳过支付回调（操作 B）。
3. 记录服务端实际生成的订单/账户变化（状态 C）。**写操作必须可控可回滚**——如可取消订单/找回原值，或单次且金额极小；不可回滚的写操作（改他人密码）改回并用测试账号验证。
4. 任意密码重置：在**自己的测试账号**上验证验证码可绕过/响应泄露/接口未鉴权，绝不能改真实用户密码。

**误报排除**：前端校验但服务端拒绝 = 非漏洞；修改后服务端返回校验失败 = 已防护；截到的"成功"是前端假象（未刷新账户数据）。

## 信息泄露 —— 低危~中危（核心数据可高危）

**验证步骤**：
1. `.git` 泄露：访问 `/.git/HEAD` 返回 `ref: refs/...` → 用工具还原**仅证明源码存在**，列出文件树即可，不下载全部、不在源码里翻真实凭据后扩散。
2. `.env`/配置文件/备份包：GET 返回真实内容 → 记录其中键名（DB_HOST 等）与 1 个脱敏样例值。
3. API 未鉴权：不带任何 Cookie/Token 直接请求，返回真实业务数据（状态 C，正常应 401）→ 对照带鉴权的响应（状态 A）。
4. 目录列表：确认列出的是敏感目录（含备份、日志、上传私货），公共静态资源目录不算。
5. 取证：截图打码，正文用 `138****5678` 格式脱敏。

**误报排除**：默认欢迎页/空目录；`.git/HEAD` 200 但其余 404（需证明可还原出对象）；返回数据是公开接口数据；CDN 缓存的公开页面。

## XSS —— 低危~中危

**验证步骤**：
1. 存储型：在个人资料/评论等输入点提交无害标记 payload（如 `<svg/onload=alert(document.domain)>` 或仅 `<b>xss-test-<random>` 观察反射点），**自己**的会话里确认执行；弹窗截图需带 document.domain 与随机标记。
2. 反射型：确认参数原样输出且未过滤（对比大小写、编码绕过尝试）。
3. 取证：输入点 URL、payload、触发截图、（存储型）他人视角可见证明。

**误报排除**：输出被实体编码；payload 存进了库但渲染时被过滤；只有自己可见的"存储型"（自 XSS）不算。alert 弹窗是通用做法，注意不要用会伪装成系统提示的大段内容。

**定级要点**：存储型 > 反射型；核心后台存储型可中危；纯反射且需诱导 = 低危。

## 文件上传 —— 中危~高危

**验证步骤**：
1. 上传无害探测文件：`test-<random>.txt`、改 Content-Type、双后缀 `test.jpg.txt`、`.phtml` 等变体。
2. 判断服务端校验逻辑与实际解析风险。**证明可上传到 Web 可访问路径且能被解析执行**才算漏洞；若仅能传 jpg 但服务器不解析脚本，则不构成漏洞。
3. 探测文件内容只用无害标记文本（如 `<?php echo "butian-verify-<random>"; ?>` 之类最小验证），**禁止**上传功能性 webshell；验证完成立即请求删除或记录待厂商清理，报告中注明。
4. 若上传成功但无法证明解析（如无法访问），降级记录为"上传限制不足"线索。

## SSRF —— 中危

**验证步骤**：
1. 找带 URL 参数的功能（URL 预览、导入、webhook、头像拉取）。
2. 用自建/dnslog 外带证明服务器发起请求；尝试 `file://`、内网地址（`http://127.0.0.1`、`http://169.254.169.254` 云元数据）只看响应差异，**不利用元数据凭据**。
3. 证明"服务器端发起任意/受限请求"即可。

**误报排除**：请求由浏览器发出（检查响应与网络面板）；目标白名单校验生效；外带失败可能是出网限制（本身是防护，记录说明）。

## 已知组件 CVE（通用漏洞重点）—— 视 CVE 定级

**验证步骤**：
1. 指纹精确到版本号（页面 footer、`/readme`、composer.json、报错页、特殊路径）。
2. 核对 CVE 影响版本与补丁区间，确认目标版本落在受影响区间。
3. 用官方 PoC 的**最小无害验证**（如仅需证明特征响应/触发异常即可的 payload）。
4. 通用漏洞按补天口径：第三方软件/应用/系统的漏洞属于通用漏洞，可提交通用通道；提交时写清影响版本范围与利用条件。

**误报排除**：指纹误识别（版本号来自缓存或错误页面）；版本受影响但漏洞路径被安全配置禁用；Nuclei 通用模板命中但目标实际是蜜罐/仿真页——通用漏洞刷洞重灾区，务必用自定义 payload 二次确认。

## 验证结论写法（写入 verify-notes.md）

每个验证完的漏洞按此格式下结论，报告中"危害证明"一节直接引用：

```
漏洞编号：V-20260828-001
验证时间：2026-08-28 21:34 (+08:00)
验证环境：无痕会话 / curl 8.x / poc.py / 目标 example.com（补天 XX 项目收录）
工具链：①专业工具[sqlmap --dbs 确认] → ②定制PoC[poc.py 布尔对照+取库名] → ③取证[curl -v + 浏览器截图]
闭环记录：
  A（修改前）：GET /api/user/1001 (账号A会话) → 返回账号A的姓名与手机号（已脱敏）
  B（操作）  ：会话不变，改 GET /api/user/1002
  C（修改后）：返回账号B的姓名与手机号 → 水平越权成立
影响结论：任意登录用户可遍历读取全站用户信息（接口返回受 id 枚举限制）
最小影响声明：仅读取 2 条记录取证，未批量拉取，证据已脱敏
重现性矩阵：会话1 第1次✓ 第2次✓ / 会话2(无痕) 第3次✓ / 跨时间点 第4次✓（全部一致）
PoC：evidence/<漏洞编号>/poc.py，末行输出 VULNERABLE（可重复运行）
```
