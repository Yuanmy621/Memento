> 生成报告与填写提交表前必读。本文内容于 2026-08 通过登录态浏览器逐屏读取补天官方页面整理：

## 1. 漏洞提交流程（官方"总体原则"）

1. **提交漏洞**：补天安全专家看到漏洞详情后给出合理报价。
2. **验证初审**：对白帽子提交的漏洞详细进行验证并初步确认奖励，如没有通过则本次漏洞提交过程结束。
3. **通知厂商**：补天官方第一时间通知相关厂商和国家漏洞库等。
4. **定价**：发放 kb 奖励（如果无法联系厂商但危害大的漏洞会坚持给出定价；但如果厂商表示已通报过或者积极拒绝修复，可能不会定价）。
5. **结束**：本次漏洞提交过程结束。

**厂商悬赏奖励**分三类：现金奖励（直接给予现金）、KB 奖励（可兑换礼品）、荣誉奖励（rank 奖励、榜单公示、积分排行）。漏洞奖励为现金或者 KB 单一奖励。

## 2. DREAD 评级模型（官方漏洞定级核心）

适用于系统及通用软件漏洞等级评定（页面同时以 DREAD 评价示例演示通用评级思路）。参考：https://www.anquanke.com/post/id/161442

- 风险等级范围 1–10：**1–4 低危、5–7 中危、8–10 高危**
- **计算公式：风险等级 = 潜在损失(D) + 重现性(R) + 可利用性(E) + 受影响的用户(A) + 可发现性(D)**，每维 0/1/2 分
- 定义上述问题后计算风险等级值(0–2)，结果范围 0–10；因为风险等级定义为 1-10，故将 0 也做为最低值 1

| 维度 | 高危（2分） | 中危（1分） | 低危（0分） |
|---|---|---|---|
| D 潜在损失 | 攻击可以暗中破坏安全系统，获取完全信任的授权，以管理员身份运行程序、上传内容 | 泄露敏感信息 | 泄露价值不高的信息 |
| R 重现性 | 攻击每次可以重现，且不需要时间间隔 | 每次可重现，但只在特定时间间隔和特定竞争条件下 | 攻击很难重现，即使很了解安全漏洞 |
| E 可利用性 | 编程新手在短时间内就可以进行（如 sqlmap 默认配置即可获取信息） | 熟练编程人员可以进行并重复这些步骤 | 需要非常老练的人员，且对每次攻击有深入了解 |
| A 受影响用户 | 所有用户，默认配置，主要客户 | 一些用户，非默认配置 | 极少用户，特点不明确，影响匿名用户 |
| D 可发现性 | 公开解释攻击的信息，可在最常用功能中找到，非常明显 | 很少使用部分的缺陷，少量用户可能遇到，需花心思判断 | 错误不明显，用户不可能引起潜在损失 |

**官方示例：SQL注入 = 潜在损失2 + 重现性2 + 可利用性2 + 受影响用户1 + 可发现性1 = 9 分 → 高危**
（SQL 注入潜在损失通常 2 分最高；重现性无特殊情况应为 2 分；5 种评分都可根据实际情况调整。）

**报告落地用法**：自评等级时按此公式逐维打分并写出总分，作为"危害等级自评"的理由；Web 漏洞的定级另需对照 §4 的官方三档描述。

## 3. 漏洞定义与关注类型（Web 漏洞）

- **通用漏洞**：第三方软件、应用、系统对应的漏洞。如 ECShop、Discuz、PHPCMS 的 SQL 注入、XSS 漏洞；开源软件、安全浏览器、手机应用、路由器、开发框架，甚至是 VPN 系统或某防火墙系统的漏洞。
- **事件漏洞**：非通用型漏洞，指互联网上应用的一个具体漏洞。如 xx 网站命令执行可被渗透、xx 电商订单漏洞任意充值、xx 网站应用 SQL 注入可导致信息泄露等。

**关注的 10 类 Web 漏洞类型**（如有未涉及且危害严重的类型，欢迎补充）：
1. XSS 2. SQL注入漏洞 3. 命令执行 4. 代码执行 5. 文件包含 6. 任意文件操作 7. 权限绕过 8. 逻辑漏洞 9. 信息泄露 10. 存在后门

**收录范围**：专属 SRC、公益 SRC 以及未注册厂商漏洞。未注册厂商根据权重不同，奖励有所不同。gov/edu 漏洞有单独权重要求。**IP 漏洞暂不收取**。
**特别说明：奇安信集团及旗下关联公司员工，不适用于补天平台所有漏洞奖励计划（含补天公益、专属 SRC、补天众测、五星计划、通用漏洞奖励等）。**

## 4. Web 漏洞等级（官方定义，评级可按可利用性和影响调整）

调整影响因素包含：厂商权重、网站流量、攻击复杂度、对被测目标的影响、漏洞利用的权限需求、影响范围、机密性以及完整性等。

**高危**：
1. 直接获取服务器权限的漏洞，包括但不限于任意命令执行、上传 webshell、任意代码执行。
2. 直接导致严重的敏感信息漏洞，包括但不限于大量敏感信息泄露漏洞。
3. 支付类型逻辑漏洞，包括但不限于影响盈利的资金逻辑漏洞。
4. 能直接盗取用户身份信息的严重漏洞；可获取大量敏感信息或者执行命令的 SQL 漏洞。
5. 直接导致严重影响的逻辑漏洞；可重置管理员的密码，且导致大量敏感信息泄露漏洞。

**中危**：
1. 能直接盗取用户身份信息的漏洞，包括但不限于一般的 SQL 注入漏洞（需证明可获取数据库名/用户名）。
2. 直接导致相对严重影响的逻辑漏洞，包括无法导致较大敏感信息泄露的管理员用户密码重置或普通用户密码重置。
3. 需交互才能获取用户身份信息的漏洞，包括但不限于存储型 XSS 漏洞。
4. 任意文件操作漏洞，包括但不限于任意文件读、写、删除、下载等操作。
5. 越权访问，包括但不限于绕过认证许可后，绕过限制修改用户资料、执行用户操作。
6. 比较严重的信息泄露漏洞，包含敏感信息泄露（如 DB 连接串）。
7. 弱口令（不含前台弱口令）。

**低危**：
1. 普通逻辑漏洞，包括但不限于 redis 未授权、heapdump 敏感信息泄露、短信轰炸等。
2. 需交互才能获取用户身份信息并且有一定利用难度的漏洞。
3. 其他低敏感数据类问题。

## 5. 事件漏洞奖励（按厂商权重分四档）

1. **厂商相对较小**：低危 1-2KB（redis未授权、heapdump敏感信息泄露、短信轰炸等）；中危 2-3KB（敏感信息泄露、越权、sql注入等）；高危 4-6KB 或 ¥100-¥200（任意命令执行、泄露数据量较大等）
2. **中大型厂商**（电信、移动、联通三大运营商、高权重站点）：低危 2-4KB；中危 4-6KB；高危 8-12KB 或 ¥100-¥300
3. **大厂**（新浪、网易、京东、百度、字节跳动、阿里、快手、腾讯等互联网巨头）：低危 3-6KB；中危 6-9KB；高危 12-18KB 或 ¥200-¥600
4. **权重为 0 的厂商**（以市场价为准）：低危 100-200 荣誉币；中危 200-300 RYB；高危 400-600 RYB

日常每个白帽每个月仅限前 100 个有效漏洞发放荣誉币，超出无荣誉币奖励（以补天活动中心/任务中心公告为准）。

**降低或忽略奖励的情形**（包括但不限于）：
1. 无实际危害或危害太小的漏洞：url 跳转、前台个人弱口令、任意用户注册、self-xss、邮件轰炸、CORS 配置错误、Web 安全盒缺失或安全响应头缺失泄露等
2. 无法直接利用的数据或信息：内网信息泄露、已过期的 key 等
3. 对网站具有破坏性的操作：拒绝服务类漏洞
4. 无敏感信息的漏洞：已脱敏的信息、公开文件、api 接口泄露但无有效信息等
5. 同一系统同类型漏洞超过三个的漏洞不再发放奖励或忽略处理
6. SQL 注入按漏洞接口计算，同一接口多个参数存在注入算一处
7. 由通用产品厂商漏洞产生的不同企业事件型漏洞，平台累计收录超过 50 个后奖励降为 1KB 一个
8. **未经人工验证的 AI 生成的漏洞（多次提交可能面临封号风险）** ←官方原文，本技能的人工核验关卡由此而来

注：所有降低奖项的漏洞积分不得降级；鼓励挖掘原创漏洞，不鼓励刷同类型同思路漏洞，同类型漏洞可提交到通用型。

## 6. 通用漏洞奖励（重点应用 vs 小众厂商）

| 应用类型 | 具体应用（不断更新） | 高危 | 中危 | 低危 |
|---|---|---|---|---|
| 重点应用 | tomcat、solr、apache 等顶级中间件或 web 应用；国内具有行业影响力的应用（跨行业/某行业影响较大）；大型开源/漏洞 Web 系统 | ¥1000-10000 | ¥500-3000 | ¥200-600 |
| 小众厂商 | 有一定使用量的建站系统、各类 CMS、使用同一模板的 Web 应用 | ¥50-500 | 5kb-¥100 | 3-10kb |

1) 奖励方案限于获取核心数据或对系统造成严重影响的漏洞；平台严格按漏洞等级划分做危险等级评估。
2) 网上已知漏洞的二次利用（如 struts2 漏洞、ThinkPHP 框架漏洞等）或官方补丁的 bypass，综合评估后给奖。
3) 漏洞分析有技术难点可以参加加分。
4) 小众厂商应用无法下载到源码的，请至少提供 10 个以上的案例。
5) 不同文件下的同一参数、不同目录下的同一文件、同一目录下的相似文件，或同一类型漏洞，平台会选择性做合并处理。
6) 不鼓励刷洞行为，如出现刷洞或提交无意义漏洞等情况，将降低评价处理。
注：鼓励挖掘高危害、影响范围大的漏洞；影响范围小、无人维护的企业建站公司漏洞会酌情评价，重点应用漏洞会酌情加价。**基于后台登陆的漏洞，以及弱口令漏洞，通用类型一般不考虑收取。**

**小众厂商奖励**：漏洞组合或漏洞打包提交（中高危漏洞不少于 3 个）¥300-¥1000。注：有些企业建站公司漏洞影响太小且难以推动修复，已不再收集。

## 7. 提交模板（官方《补天平台规范化提交漏洞须知》）

> 官方要求：白帽子需尽可能清晰地描述漏洞细节，提交后积极支持厂商重现和修复，**务必依照模板规范化提交漏洞，以避免影响审核结果**。以 SQL 注入为例，按规范标准提交的漏洞可获得优先审核权益。

### 7.1 公益 SRC 提交模板字段（对应提交表单）

| 表单字段 | 填写要求 |
|---|---|
| 漏洞URL | URL 地址；**GET 类型的注入需要在提交处提交完整的参数拼接 URL**；格式以 http:// 或 https:// 开头 |
| 补充URL | **注入类型为 POST 时需要填写**此处 |
| 漏洞类型 | 下拉选择（如：弱口令、SQL注入；分事件型/通用型） |
| 漏洞描述/数据包框 | **POST 类型的注入需要在此处提交完整的数据包**；当多个数据包打包提交时只需要在其中填入一个即可；注入参数需单独填写 |
| 漏洞等级 | 下拉选择（低危/中危/高危） |
| 漏洞权重 | **公益和未注册厂商必选**：以主域名的爱站权重为准——百度/百度移动 ≥1 或谷歌 ≥3 请选权重大于等于 1，否则请选权重 =0；**权重为 0 的厂商务必选择权重=0，选错/漏选将驳回** |
| 选择参与的活动 | 如未选择活动默认不参与奖励计划（活动在活动中心报名，不定期上线，为额外奖励） |
| 选择参与的任务 | 如未选择任务则默认不参与（任务在个人空间领取，为额外奖励） |
| 附件 | 支持上传压缩包/图片/文件形式，**单个不能超过 5M**；证明材料打包上传 |
| 修复方案 | 必须认真填写（乱填、凑字会被扣分/驳回） |
| 所属行业 / 行业分类 / 所属地区 | 按厂商主营业务选择其所属行业（行业分类准确性影响厂商权重评定），填写厂商所在省市 |
| 厂商联系方式 | 有则填写 |
| 留名/留QQ | 可选留名提交（未开放白帽子名称显示时显示为"匿名大佬"）或留 QQ |

**证据四件套（官方模板要求全部标明，配图示例）**：
1. **漏洞 URL**：浏览器地址栏完整 URL 截图
2. **归属证明**：百度搜索"关键字 补天漏洞响应平台"的结果截图（证明目标归属补天平台收录）
3. **首页截图**：目标站点首页截图
4. **漏洞证明**：漏洞利用成功的证明截图（官方示例：工具执行 whoami 验证 shiro 反序列化，回显 `nt authority\system`）

**漏洞利用描述要求**（红字提示）：
1. 漏洞利用的完整过程：相关 URL、截图、代码及 POC，若不符合规则，漏洞可能会审核不通过。
2. IoT 漏洞还需提供：漏洞触发对应的二维码/抓包位置、目标配置截图、漏洞证明视频（实硬件设备提供相关环节；模拟仿真需描述环境搭建及调试方法）。
3. 漏洞利用过程中使用到工具的，提供下载链接或压缩包。

### 7.2 专属 SRC 提交模板字段

接收范围（厂商名称、厂商测试范围、主域名）→ 漏洞名称（如"Web漏洞"）→ 漏洞地址（如"xx系统网站业务存在xx漏洞"）→ 漏洞URL → 漏洞类型 → 漏洞等级 → 漏洞描述 → **详细描述**（须包含：存在漏洞的对应服务的漏洞以及后台地址；漏洞详细操作流程、poc、以及这些步骤和 poc 中涉及数据的截图和抓包信息——**提供到能复现即可**）→ 附件（≤5M）→ 修复方案（认真填写）→ 所属行业/行业分类/所属地区 → 厂商联系方式 → 留名/留QQ。

## 8. 其他漏洞品类的收录要点（/Help/plan）

- **IoT 漏洞**：分通用管理接口类、通用协议类、私有协议类。凡涉及服务端交互、修复在服务端进行的提交 WEB 漏洞；需要重新编译或修改配置修复的为 IoT 漏洞。平台仅收集 IoT 设备**默认服务/默认配置**下产生的漏洞，要求影响最新固件版本，同一固件设备收录前 3 个漏洞。等级 16 条细则（root shell/硬编码账户/重要DB注入为高危；需合法权限的命令执行、设备级拒绝服务为中危；SN/PIN 泄露、反射 XSS、URL 跳转为低危）。奖励按厂商规模分三档（厂商相对较小 / Netgear、Dlink、TPlink 等 / Cisco、华为等），高危 ¥100-¥200000 不等；**思路比较新颖、影响范围大的可单独询价（一洞一议）**。
- **移动 App 漏洞**：凡涉及服务端交互、修复在服务端进行的提交 WEB 漏洞；需重新发布版本或修改配置修复的为移动 App 漏洞。高危：无需/单次用户交互的远程任意代码执行、远程任意文件读写、大规模敏感信息泄露；中危：单一用户敏感信息泄露、权限滥用、应用本地代码执行；低危：应用本地 DOS、需特殊触发条件的漏洞。奖励分中小型/中大型厂商两档（如远程任意 Native 代码执行 ¥200-5000）。
- **工控漏洞**：必须是**未公开 0day**，建议附漏洞检测报告（CVE/CNVD/CNNVD/ICS/Seebug 等）；**必须给出详细复现步骤（软件下载链接、利用代码、原理描述、环境描述、完整流量、记录视频），复现失败作忽略处理**；高中危评价参考 CVSS（平台内部用 IVSS：攻击向量/攻击复杂度/特权要求/用户交互/机密性/完整性/可比性/可能性/可控性等指标，评分低危 0.1~3.9、中危 4.0~6.9、高危 7.0~10.0）；厂商分大/中/小型（大型限定施耐德、西门子、ABB、GE、霍尼韦尔等；不能确认员工数与年收入的定义为小型）。dll 劫持类只收知名厂商且每类软件不超 3 个；RTU < PLC(小/中/大) < DCS < SIS 分级计价；**对于有争议的漏洞（复现出问题/价格争议），平台有权拒收**。
- **系统及通用软件漏洞**：范围含操作系统、网络/安全设备、第三方应用软件、协议认证、Web 中间件、数据库、开发环境、第三方依赖库、大平台组件。关注类型：远程执行、拒绝服务、权限提升、代码执行、溢出漏洞、虚拟逃逸、其他。等级采用 §2 DREAD 模型；奖励与漏洞价值有关，依据市场价格发放。

## 9. 其他平台规则（官方 FAQ，未变）

- 审核时效：公益 SRC/未注册厂商——补天审核后联系厂商认领，7 天无人认领由平台确认；专属 SRC——补天初审约 1 个工作日，厂商复审一般一周内，超一周未复审自动通过。
- 数量限制：新用户未产出有效漏洞前最多 5 个待审核漏洞，产出 1 条有效漏洞后解除。
- 重复判定：以提交时间排序为准。
- 违规：信誉值共 100；刷洞、一洞多投、抄袭转载扣 10 分（专属 SRC 扣 20），≤60 封号。
- 争议：官方 QQ 群 1015536219 联系审核人员（备注漏洞编号+用户名）；白帽咨询 010-56509093。

## 10. 对本技能的落地要求（由官方规则推导）

1. **自评定级必须双轨**：先按 DREAD 五维打分给出总分与档位，再对照 §4 官方高危/中危/低危描述核对，两者取一致结论并写明理由。
2. **证据按"四件套"组织**：漏洞URL截图、归属证明、首页截图、漏洞证明——生成报告时把 `out/evidence/` 的文件按这四类命名对齐。
3. **权重选择写进提交表**：提醒用户按爱站权重选权重档位，权重0厂商必须显式选 0，否则驳回。
4. **AI 原文红线**：未经人工验证的 AI 生成漏洞多次提交可能封号——报告必须附人工核验清单，提交者本人复现后再提交。
5. **避免进忽略清单**：url 跳转、self-xss、CORS、邮件/短信轰炸、过期 key、无敏感信息的 api 泄露、拒绝服务测试等不做为主要目标；同一系统同类型漏洞只报最优的一个；SQL 注入按接口去重。
6. **通用漏洞选题**：重点应用（中间件/有行业影响力的系统）价值最高；后台登录后的漏洞和弱口令一般不收通用。
