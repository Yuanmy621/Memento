# 漏洞报告模板（漏洞盒子 · 企业 SRC）

> 口径来源：帮助中心 [97] 优秀的报告标准、[79] 平台通用评定原则、[94] 漏洞评级标准参考、
> [150] 关于规范 AI 辅助漏洞报告提交标准。**填之前先读一遍这四篇**（`vulbox_help id=`）。
>
> 硬规则（会被驳回的写法）：
> - 纯 AI 推测、没有真实请求包 / 响应 / 截图的报告 → **无效**，累计 3 个警告、5 个限权 [150]；
> - 只有报错、没有危害证明的 SQL 注入 → 忽略；**严禁拖库**，注出一条数据即可 [79]；
> - 越权/未授权类只验证到「能证明」为止，**不得获取、留存用户数据** [106]；
> - 同一漏洞源引起的多个问题**合并**为一个；同系统短时间 >3 个同类高危会被合并/降级 [79]。
